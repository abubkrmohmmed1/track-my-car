# نظام تتبع واستعادة المركبات (Track My Car - TMC)

نظام إلكتروني متكامل لتنظيم بلاغات المركبات المفقودة والمعثور عليها في السودان، مبني استناداً إلى **الفصل الثالث (تحليل النظام)** ومخططات الـ **UML** المرفقة (مخطط حالات الاستخدام، مخطط النشاط، مخطط الفئات، ومخطط التتابع).

---

## 🚀 طريقة التشغيل السريعة (بدون أي تعقيد)

النظام مبني بتقنيات الويب القياسية المحددة في وثيقة التحليل (`PHP`, `MySQL / MariaDB`, `HTML/CSS/JS`)، ولا يتطلب أي تثبيت لمكتبات خارجية معقدة.

### 1. التشغيل المباشر عبر خادم PHP المدمج:
افتح موجه الأوامر (Terminal أو PowerShell) في مجلد المشروع ونفّذ:
```bash
php -S localhost:8000
```
ثم افتح متصفحك على الرابط:
👉 **[http://localhost:8000](http://localhost:8000)**

### 2. التشغيل عبر برنامج XAMPP / WampServer:
1. انسخ مجلد المشروع `TMC` إلى مسار `htdocs` داخل XAMPP (مثل `C:\xampp\htdocs\TMC`).
2. شغّل خدمتي **Apache** و **MySQL** من لوحة تحكم XAMPP.
3. استورد ملف قاعدة البيانات `database/schema.sql` عبر phpMyAdmin (قاعدة البيانات باسم `tmc_db`).
4. افتح المتصفح على: `http://localhost/TMC`.

> **ملاحظة ذكية:** يدعم ملف الاتصال `config/db.php` قاعدة بيانات **MySQL** الرسمية، وفي حال كان خادم MySQL متوقفاً محلياً، ينتقل تلقائياً إلى قاعدة بيانات SQLite محلية لتشغيل ومعاينة النظام فوراً دون أي عوائق.

## 🔑 حسابات الدخول التجريبية الجاهزة للاختبار

تم تزويد النظام ببيانات أولية مطابقة لسيناريوهات مخططات الـ UML:

| نوع الحساب | البريد الإلكتروني | كلمة المرور | الدور والصلاحيات |
| :--- | :--- | :--- | :--- |
| **مدير النظام (Admin)** | `admin@tmc.sd` | `password123` | مراجعة البلاغات، التحقق، تشغيل محرك المطابقة، وإدارة المستخدمين |
| **صاحب سيارة مفقودة** | `mohammed@example.com` | `password123` | تسجيل بلاغ فقدان، متابعة حالة البلاغ، واستقبال إشعار التطابق |
| **باحث / مُبلّغ** | `osman@example.com` | `password123` | الإبلاغ عن سيارة تم العثور عليها والبحث في البلاغات |

*(توجد أزرار تعبئة سريعة في صفحة تسجيل الدخول لتسهيل التجربة بنقرة واحدة).*

## 📂 بنية المشروع (Project Structure)

```text
TMC/
│
├── config/
│   ├── db.php                  # الاتصال بقاعدة البيانات (PDO)
│   └── app.php                 # الدوال المساعدة، إدارة الجلسات، ورفع المرفقات
│
├── api/                        # واجهة البرمجة (RESTful Endpoints)
│   ├── auth.php                # تسجيل الدخول، إنشاء الحساب، الخروج
│   ├── lost_reports.php        # إدارة بلاغات الفقدان والمرفقات
│   ├── found_reports.php       # إدارة بلاغات العثور على المركبات
│   ├── search.php              # محرك البحث السريع والفلترة
│   ├── admin.php               # لوحة الإدارة ومحرك المطابقة الآلي
│   └── notifications.php       # جلب وتحديث الإشعارات للمستخدم
│
├── assets/
│   ├── css/
│   │   └── style.css           # التصميم وتنسيقات RTL والتجاوب مع الجوال
│   └── js/
│       └── api.js              # مكتبة العميل للتواصل مع الـ API
│
├── pages/                      # صفحات النظام
│   ├── login.html              # تسجيل الدخول
│   ├── register.html           # إنشاء حساب جديد
│   ├── report_lost.html        # نموذج تسجيل سيارة مفقودة
│   ├── report_found.html       # نموذج الإبلاغ عن سيارة تم العثور عليها
│   ├── my_reports.html         # بلاغاتي وصندوق الإشعارات
│   └── admin.html              # لوحة تحكم مدير النظام ومحرك المطابقة
│
├── database/
│   ├── schema.sql              # سكريبت إنشاء جداول MySQL والبيانات الأولية
│   └── init_db.php             # فحص واختبار صحة قاعدة البيانات
│
├── uploads/                    # مجلد حفظ صور المركبات والمستندات
├── sessions/                   # حفظ جلسات المستخدمين بأمان محلياً
└── index.html                  # الصفحة الرئيسية ومحرك البحث العام
```

## 📋 مطابقة النظام مع مستندات الفصل الثالث (Traceability Matrix)

| المتطلب في الفصل الثالث / مخطط UML | كيفية التحقق والتنفيذ في الكود |
| :--- | :--- |
| **مخطط حالات الاستخدام (Use Case)** | تم تنفيذ جميع الوظائف: إدارة البلاغات، مراجعة البلاغات، تسجيل بلاغ فقدان وعثور، إرفاق مستندات، البحث، واستقبال الإشعارات. |
| **مخطط النشاط (Activity Diagram)** | دورة حياة البلاغ تبدأ من `قيد المراجعة` -> مراجعة الإدارة (هل مكتمل؟ -> `يتطلب استكمال البيانات` أو `منشور`) -> هل يوجد تطابق؟ (`يوجد تطابق محتمل` وإشعار الأطراف). |
| **مخطط الفئات (Class Diagram)** | جداول قاعدة البيانات مطابقة 1:1 للفئات: `users`, `vehicles`, `lost_reports`, `found_reports`, `attachments`, `notifications` (مع إضافة رقم الشاسيه وتصنيف المرفقات). |
| **مخطط التتابع (Sequence Diagram)** | تسلسل العمليات بين واجهة النظام، الخادم، قاعدة البيانات، ونظام الإشعارات متطابق بالكامل. |
| **محرك المطابقة (Matching Engine)** | خوارزمية ذكية في `api/admin.php` تقارن رقم اللوحة، الشركة المصنعة، الطراز، اللون، وسنة الصنع لحساب نسبة التطابق (0-100%). |
| **التحقق من المركبات منزوعة اللوحات** | نماذج تسجيل الفقدان والعثور تدعم رفع صور مصنفة: (صورة عامة للمركبة، صورة اللوحة، وصورة واضحة لمكان رقم الشاسيه) للتحقق الإضافي الموثوق. |
